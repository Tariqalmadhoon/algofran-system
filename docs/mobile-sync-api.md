# عقد مزامنة تطبيق المحفّظ للجوال

جميع المسارات تحت `/api/v1` وتستخدم `Authorization: Bearer <token>` بعد تسجيل الدخول. المصدر الرسمي للبيانات هو Laravel/MySQL؛ التخزين المحلي في الهاتف طابور مؤقت وآمن.

## 1. تسجيل الجهاز

`POST /auth/login`

```json
{
  "email": "teacher1@gofran.com",
  "password": "********",
  "device_name": "تطبيق مركز الغفران",
  "device_uuid": "3c3f6e9b-8d61-4b46-8be5-18bd8d9cbfac",
  "platform": "android",
  "app_version": "1.2.0"
}
```

يحصل المحفظ الفعال على `mobile:read` و`mobile:sync`. ويضاف `mobile:export` عندما يملك الحساب صلاحية تصدير التسميع. الحساب الذي لا يملك `recitations.create` و`attendance.manage` لا يحصل على صلاحية المزامنة.

## 2. تهيئة البيانات المحلية

`GET /mobile/bootstrap?device_uuid=<uuid>`

يعيد:

- ملف المحفظ.
- حلقاته الفعالة وطلابه الملتحقين.
- صلاحيات إضافة الطلاب وتعديلهم وأرشفتهم في وضع الجوال.
- ملف كل طالب، ومؤشرات تقدمه، وإنجازاته، وآخر سجلاته للاستخدام دون اتصال.
- حالة تسجيل كل طالب اليوم.
- السور والآيات اللازمة للعمل دون إنترنت.
- خيارات الحضور والتقييم وأنواع التسميع.
- `sync_cursor` لجلب التغييرات اللاحقة.

الإصدار الحالي من الحمولة هو `schema_version: 3`. لا تتضمن الحمولة رقم هوية الطالب أو بيانات ولي الأمر أو وثائق الهوية؛ قاعدة Drift المحلية ليست مخزنًا مناسبًا لهذه البيانات الحساسة.

## 3. دفع السجلات المحلية

`POST /mobile/sync/daily-records`

الحد الأقصى 50 عملية في الدفعة. تعالج كل عملية منفردة، لذلك لا يمنع سجل غير صالح اعتماد بقية الطلاب.

```json
{
  "device_uuid": "3c3f6e9b-8d61-4b46-8be5-18bd8d9cbfac",
  "operations": [
    {
      "operation_uuid": "a3537c23-c744-40b2-af9a-5f6672d87fb8",
      "client_created_at": "2026-08-30T12:30:00Z",
      "daily_record": {
        "student_id": 6,
        "halaqa_id": 28,
        "record_date": "2026-08-30",
        "attendance_status": "present",
        "attendance_notes": null,
        "general_evaluation": "very_good",
        "notes": null,
        "items": [
          {
            "type": "new_memorization",
            "start_ayah_id": 6231,
            "end_ayah_id": 6236,
            "evaluation": "very_good",
            "memorization_errors": 1,
            "tajweed_errors": 0,
            "hesitation_count": 0,
            "teacher_prompt_count": 0,
            "notes": null
          }
        ]
      }
    }
  ]
}
```

حالات النتيجة:

| الحالة | المعنى |
|---|---|
| `accepted` | تم إنشاء واعتماد السجل رسميًا |
| `already_processed` | العملية نفسها وصلت سابقًا؛ أعيدت نتيجتها دون تكرار |
| `conflict` | يوجد سجل رسمي آخر أو أعيد استخدام UUID ببيانات مختلفة |
| `rejected` | فشل التحقق من الصلاحية أو الإسناد أو البيانات |
| `failed` | عطل مؤقت، ويمكن إعادة العملية بالـUUID نفسه |

يعيد `summary` عدادات منفصلة لـ`accepted` و`conflicts` و`rejected` و`failed` حتى يميّز التطبيق بين الرفض النهائي والعطل المؤقت القابل لإعادة المحاولة.

## 4. جلب تغييرات الخادم

`GET /mobile/sync/changes?device_uuid=<uuid>&cursor=<cursor>&limit=100`

يعيد سجلات المحفظ فقط مرتبة حسب `updated_at` و`id`، مع `next_cursor` و`has_more`. يجب حفظ المؤشر محليًا بعد نجاح معالجة الصفحة.

## 5. مزامنة إدارة الطلاب

`POST /mobile/sync/student-operations`

تقبل الدفعة حتى 50 عملية مستقلة من الأنواع `create` و`update` و`archive`:

- `create`: يرسل التطبيق `client_uuid` ثابتًا والحلقة والأسماء الأربعة وتاريخ التسجيل والحقول غير الحساسة. يولد الخادم `student_number` المتسلسل ويعيد معرّف الطالب الرسمي.
- `update`: يرسل `id` و`base_updated_at` والحقول القابلة للتعديل. إذا تغير الملف على الخادم بعد آخر مزامنة يعاد `student_changed_on_server` ولا تُكتب البيانات القديمة فوق الجديدة.
- `archive`: أرشفة وظيفية وليست حذفًا نهائيًا؛ تنتهي عضوية الحلقة ويُحفظ تاريخ الحضور والتسميع والإنجازات.

إذا أنشئ الطالب وسُجل له تسميع أثناء انقطاع الإنترنت، يرسل التطبيق عملية إنشاء الطالب أولًا، ثم يستبدل `client_uuid` بالمعرّف الرسمي داخل معاملة محلية، وبعدها يرسل السجل اليومي.

## 6. الملفات والتصدير

- `GET /mobile/profile`
- `GET /mobile/students/{student}/profile`
- `POST /mobile/report-exports`
- `GET /mobile/report-exports/{uuid}`
- `GET /mobile/report-exports/{uuid}/download`

إنشاء ملف Excel وتنزيله أول مرة يحتاجان اتصالًا بالخادم لأن التقرير يبنى من MySQL الرسمي. بعد تنزيل الملف يحتفظ التطبيق بمساره ويمكن فتحه دون اتصال. جميع المسارات محصورة بحلقات المحفظ وبمالك ملف التصدير.

## الضمانات

- قيد فريد على `الجهاز + operation_uuid`.
- بصمة SHA-256 للحمولة تمنع إعادة استخدام UUID ببيانات مختلفة.
- قيد قاعدة البيانات `الطالب + التاريخ` يمنع السجل اليومي المكرر.
- التحقق من إسناد المحفظ والتحاق الطالب يتم بتاريخ السجل، وليس اعتمادًا على بيانات الهاتف.
- اعتماد الحضور والسجل وبنود التسميع يتم داخل معاملة واحدة.
- لا تخزن حمولة الطالب الخام في جدول إيصالات المزامنة؛ تخزن البصمة والنتيجة فقط.
