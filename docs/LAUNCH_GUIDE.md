# إطلاق مركز الغفران — algofran-center.tech

النطاق المعتمد: `https://algofran-center.tech`، وAPI: `/api/v1`، وصفحة تنزيل Android الخاصة بالمحفّظ: `/teacher/mobile-app` بعد تسجيل الدخول.

هذا دليل النشر الفعلي؛ تجهيز الملفات محليًا لا يعني أن الموقع نُشر أو أن أول دخول للجوال سيعمل قبل تشغيل API على النطاق.

## 1. تجهيز الاستضافة لأول مرة

1. فعّل SSL، واختر PHP 8.2 مع الامتدادات اللازمة لـLaravel/Excel، وافحص SSH وComposer وCron في باقتك.
2. أنشئ **قاعدة MySQL إنتاج جديدة فارغة**. لا تصدّر بيانات التجربة إليها ولا تحذف قاعدة الحاسوب. لا تستخدم `migrate:fresh` أو `db:wipe`.
3. ارفع المستودع مع `composer.lock` و`package-lock.json`، واجعل كود Laravel خارج جذر الويب. لا ترفع `.env` المحلي أو مفاتيح توقيع الجوال أو `mobile/build` كاملًا.
4. ابدأ من `.env.production.example` على الخادم فقط. النطاق مضبوط؛ أدخل بيانات MySQL وSMTP الفعلية وحساب المدير الأول بكلمة مرور قوية في `INITIAL_ADMIN_*`. `MAIL_HOST=smtp.example.com` مثال يجب استبداله. لا تستخدم `123456789`؛ فحص الإنتاج يرفضها.
5. أنشئ `APP_KEY` **مرة واحدة فقط إذا كان فارغًا**، واحتفظ بنسخة آمنة منه. اترك `TWO_FACTOR_AUTH_ENABLED=false` وفق القرار الحالي.

بعد تثبيت Composer وإعداد `.env` الصحيح على **قاعدة الإنتاج الجديدة**:

```bash
composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
php artisan key:generate
php artisan config:clear
php artisan migrate --force
php artisan db:seed --class=DatabaseSeeder --force
```

أمر `key:generate` أعلاه للتهيئة الأولى فقط، وليس في التحديثات. `DatabaseSeeder` في `production` ينشئ المرجع القرآني والصلاحيات والإعدادات والمدير الذي حددته، دون مركز أو طلاب أو سجلات تجريبية. امسح قيم `INITIAL_ADMIN_*` بعد نجاح إنشاء الحساب. ينشئ المدير مركز الغفران ثم الحلقتين والمحفظين من الواجهة، ويمكن إسناد حلقة له أيضًا.

### إذا كانت الباقة Web/Business/Cloud

مساران منفصلان، مع استبدال اسم حساب الاستضافة بالقيمة الحقيقية من hPanel:

```text
/home/ACCOUNT/domains/algofran-center.tech/alquran-app
/home/ACCOUNT/domains/algofran-center.tech/public_html
```

راجع أن `public_html` يخص الموقع وحده، وخذ نسخة احتياطية منه ثم أنشئ بداخله ملفًا فارغًا باسم `.alquran-public-root`. استخدم `BROADCAST_CONNECTION=null`. يظل تسجيل الطلاب والمزامنة والإشعارات المخزنة فعالًا؛ التصدير والطوابير يعتمدان على Cron.

نزّل Artifact الويب من Workflow `Production quality and deployment` وانقل `web-assets.tar` إلى مسار مؤقت في الخادم. تتوفر أيضًا حزمة البناء المحلية لهذه الجولة في `storage/app/private/deployment/web-assets.tar`؛ استخدمها فقط مع نفس الكود الحالي، ثم:

```bash
bash deploy/deploy-shared.sh /home/ACCOUNT/domains/algofran-center.tech/alquran-app /home/ACCOUNT/domains/algofran-center.tech/public_html /absolute/path/web-assets.tar
```

السكربت يتطلب `rsync` و`flock` وإمكانية إنشاء symbolic links. إذا لم تتوفر في الباقة فلا تعتمد هذا المسار قبل تحديد البديل. لا يحتاج Node.js في الخادم عند تمرير الأصول المبنية.

أضف مهمتي Cron كل دقيقة (أو أقل فترة متاحة في الباقة) لتشغيل `deploy/cron-shared-schedule.sh` و`deploy/cron-shared-queue.sh` مع المسار المطلق للمشروع. اضبط `PHP_BINARY` لمسار PHP 8.2 الصحيح في حسابك عند اختلافه عن `/usr/bin/php`. التفاصيل في [دليل التشغيل](PRODUCTION.md).

### إذا كانت الباقة VPS

وجّه Nginx إلى `public/`، واضبط Supervisor للعامل وReverb من الأمثلة في `deploy/`، ثم فعّل `BROADCAST_CONNECTION=reverb` وأدخل مفاتيحه ونطاقه. استخدم `deploy/deploy.sh` و`system:production-check --profile=vps`.

## 2. ربط GitHub بالتحديثات

الملف `.github/workflows/production.yml` جاهز لفحص Laravel وبناء الواجهات ثم نشر commit نفسه عبر SSH. الخطوة الأولى تحتاج نسخة مهيأة مسبقًا بالخادم.

- متغيرا Repository: `PRODUCTION_BRANCH=gofran/T1` و`AUTO_DEPLOY_PRODUCTION=false`.
- Environment باسم `production`: `PRODUCTION_URL=https://algofran-center.tech` و`PRODUCTION_HOSTING_PROFILE=shared` أو `vps`.
- الأسرار: SSH host/user/port/private key/known hosts، ومسار المشروع، ومسار public_html عند shared؛ أسماؤها كاملة في [PRODUCTION.md](PRODUCTION.md).
- جرّب التشغيل اليدوي أولًا. بعد نجاح فحص النطاق والجوال فعّل `AUTO_DEPLOY_PRODUCTION=true` إن أردت النشر عقب كل push للفرع المعتمد.

لا تضع كلمات المرور أو المفاتيح في المحادثة أو ملفات Git. عند فشل نشر بعد دخول الصيانة تبقى الصيانة مفعّلة للحماية، ولا ينفذ Workflow تراجعًا أو حذفًا لقاعدة البيانات.

## 3. نشر تطبيق Android

الإصدار المعد للنطاق: `1.3.1+5`. الملفات الثلاثة من `mobile/build/releases`:

```text
gofran-mobile-1.3.1-5.apk
gofran-mobile-1.3.1-5.apk.sha256
gofran-mobile-1.3.1-5.apk.json
```

تُجمع الملفات الثلاثة كذلك في أرشيف ZIP لتسهيل الرفع. فك الأرشيف داخل مجلد الإصدارات الخاص، ولا تستخدم ZIP بدل APK في إعداد المسار.

بصمة شهادة التوقيع العامة (لـ`ANDROID_SIGNING_CERTIFICATE_SHA256`؛ ليست كلمة مرور):

```text
7bd39762e47af3ab2539097c41158f0e5fcdd4cdba398b7e61069d5d009fe1e6
```

1. احفظ نسخة احتياطية **مشفرة** من `mobile/android/keystore/gofran-release.jks` و`mobile/android/key.properties` خارج الحاسوب. لا ترفعهما إلى الموقع.
2. ارفع ملفات الإصدار الثلاثة فقط إلى `storage/app/private/releases` في الخادم.
3. في `.env` الإنتاجي فعّل `MOBILE_APP_RELEASE_ENABLED=true` واضبط الإصدار على `1.3.1` ورقم البناء على `5` ومسار الحزمة الجديدة.
4. نفذ `php artisan config:cache`، ثم سجّل دخولك بحساب محفظ فعّال وافتح `/teacher/mobile-app` للتحقق من ظهور الإصدار وحجمه.
5. يظهر لمدير النظام في لوحة التحكم رابط «توزيع التطبيق» عند `/mobile-distribution`؛ منه يراجع حالة الإصدار، بينما يظهر زر التنزيل داخل لوحة كل محفظ فعّال فقط.
6. لا ترسل رابط تحميل عام ولا تضع APK داخل `public/`. يفتح كل محفظ لوحته، ينزّل التطبيق بعد التحقق من حسابه، ثم يثبت APK ويوافق على التثبيت من هذا المصدر. أول دخول يحتاج الإنترنت وحسابًا فعّالًا مربوطًا بحلقة، ثم يعمل التسجيل وقراءة البيانات المنزّلة دون اتصال.

من يستخدم نسخة Debug القديمة: يزامنها مع الخادم القديم أولًا ويتأكد من عدم وجود سجلات معلقة أو متعارضة قبل حذفها. لا يمكن تثبيت النسخة الرسمية فوقها لأن التوقيع مختلف. القاعدة الجديدة لا تتضمن بيانات التجربة تلقائيًا.

## 4. التحديثات اللاحقة

نشر الموقع لا يحدّث APK على الهواتف. عند تغيير شاشات Flutter أو ميزاته:

1. اختبر، وارفع رقم البناء مثل `1.3.1+5`.
2. ابنِ بنفس المفتاح، محليًا عبر `mobile/scripts/build_release_apk.ps1` أو Workflow `Signed Android release`.
3. ارفع ملفات الإصدار الثلاثة الجديدة ثم غيّر الإصدار والمسار في `.env` ونفذ `config:cache`.
4. يرى المحفظ إشعار التحديث من التطبيق، يزامن سجلاته ثم يوافق على التثبيت فوق النسخة الرسمية السابقة **دون حذف التطبيق**.

تنزيل التحديث والتحقق منه تلقائيان بعد ضغط المحفظ، لكن الموافقة على تثبيته تتم من Android وليست صامتة. نقطة التحديث والـAPK تتطلبان رمز الجهاز الخاص بالمحفّظ؛ لا يستفيد أي رابط مسرّب دون حساب محفظ فعّال. لا تستبدل ملفًا منشورًا بنفس رقم البناء. إعداد أسرار Workflow وتفاصيل التحقق موثقة في [MOBILE_DELIVERY.md](MOBILE_DELIVERY.md).

## 5. التواصل العام

قناة التواصل العامة الوحيدة هي واتساب. القيم الجاهزة في نموذج البيئة هي:

```dotenv
PUBLIC_WHATSAPP_NUMBER=972567973076
PUBLIC_WHATSAPP_DISPLAY_NUMBER="+972 56 797 3076"
PUBLIC_CENTER_LATITUDE=31.382208090207207
PUBLIC_CENTER_LONGITUDE=34.331760937834474
```

بعد النشر افحص `/contact`: يجب أن يفتح الرابط ورمز QR محادثة واتساب نفسها، وأن تعرض الخريطة الموقع الصحيح. لا تضف بريدًا عامًا أو نموذج اتصال موازٍ إذا بقي اعتماد التواصل عبر واتساب فقط.

## 6. اختبار القبول قبل توزيع الرابط

- [ ] `/up` و`/ready` يعيدان نجاحًا، و`/api/v1/meta` يعيد JSON و`X-API-Version: 1` وليس صفحة HTML افتراضية.
- [ ] فحص الإنتاج ناجح بالـprofile وجذر الويب الصحيحين؛ البريد وCron والتصدير تعمل فعليًا.
- [ ] المدير المحفظ يرى حلقته والتسجيل اليومي، والمحفظ الثاني لا يرى طلابها عبر API الجوال.
- [ ] أول دخول للجوال ينزّل بيانات الحلقة؛ إغلاقه وفتحه دون إنترنت يبقيها متاحة.
- [ ] تسجيل حفظ وحضور دون اتصال ثم إعادة الاتصال يعتمد السجل مرة واحدة فقط؛ التعارض لا يكتب فوق سجل رسمي.
- [ ] الغياب بعذر لا يسمح بالتسميع؛ التنبيهات الشهرية تظهر للمسؤولين المعنيين.
- [ ] افتح ملف طالب وإنجازاته، ثم اطلب كشف Excel وتحقق من اكتمال تنزيله عبر الطابور.
- [ ] اختبر قائمة الهاتف وطي sidebar والنوافذ والتنبيهات على هاتف وسطح مكتب، ومع تقليل الحركة.
- [ ] جرّب تحديثًا موقّعًا أعلى رقمًا على جهاز اختبار قبل تعميم أول تحديث، وتأكد من بقاء الدخول والبيانات.

فحص الوحدة والتكامل والبناء محليًا لا يحل محل هذه التجربة على باقة Hostinger والهاتف الحقيقي. لا تعطّل حماية HTTPS أو فحص التوقيع لتجاوز مشكلة نشر.
