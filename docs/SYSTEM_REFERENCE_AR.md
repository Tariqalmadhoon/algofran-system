# المرجع الشامل لنظام مركز الغفران لتحفيظ القرآن الكريم

> آخر تحديث: 2026-09-23  
> النطاق المعتمد: `https://algofran-center.tech`  
> لغة الواجهة: العربية واتجاه RTL  
> هذا المستند يصف ما هو منفّذ في المشروع، وطريقة تشغيله، والحدود التشغيلية التي يجب تجهيزها في بيئة الإنتاج.

## 1. ما هو النظام؟

نظام مركز الغفران لتحفيظ القرآن الكريم هو نظام إداري وأكاديمي متكامل لإدارة دورة العمل التالية:

```text
المركز ← الحلقات ← المحفّظون ← الطلاب ← الحضور والتسميع اليومي
       ← المراجعة والتقييم ← التقدم والتحليلات ← التنبيهات والتقارير
```

يتكوّن من ثلاثة أجزاء مترابطة:

1. موقع عام تعريفي للمركز، لا يعرض بيانات الطلاب الخاصة.
2. لوحة تحكم عربية لإدارة المركز والحلقات والطلاب والمحتوى والتقارير.
3. تطبيق Android خاص بالمحفّظين يعمل دون إنترنت بعد التهيئة الأولى ويزامن البيانات عند عودة الاتصال.

لا توجد صفحة تحميل عامة للتطبيق؛ تنزيله وتحديثه مقصوران على المحفّظين المسجّلين في النظام.

## 2. المعمارية والتقنيات

| المجال | التقنية المستخدمة |
| --- | --- |
| الخادم | Laravel 12 على PHP 8.2+ |
| قاعدة البيانات | MySQL عبر Eloquent ORM |
| واجهة لوحة التحكم | Blade + Livewire 4 + Tailwind CSS 4 + Alpine.js |
| بناء الأصول | Vite 6 وNode.js 20+ |
| الخط والهوية | Tajawal وشعار مركز الغفران |
| المصادقة | Laravel Fortify وجلسات Laravel |
| صلاحيات الويب | `spatie/laravel-permission` مع Policies وصلاحيات دقيقة |
| API الجوال | Laravel Sanctum وواجهة `/api/v1` |
| الجوال | Flutter/Dart، Riverpod، Dio، Drift/SQLite، Secure Storage |
| ملفات Excel | `maatwebsite/excel` |
| التحديثات الحية | Laravel Reverb + Echo عند تجهيز البيئة؛ يوجد fallback للإشعارات المخزنة |
| الاختبارات والجودة | PHPUnit، Laravel Pint، Vite build، GitHub Actions |

منهجية البناء هي **Modular Monolith**: قاعدة كود واحدة وقاعدة بيانات واحدة، مع فصل منطق الأعمال في Actions وServices حتى يستخدم الويب وAPI والجوال القواعد نفسها دون تكرار.

## 3. الهوية والصلاحيات

### الحسابات والأدوار

يدعم النظام الأدوار التالية:

- مدير النظام `super-admin`.
- مدير المركز `center-manager`.
- المشرف الأكاديمي `academic-supervisor`.
- المسجل `registrar`.
- المحفّظ `teacher`.
- ولي الأمر `guardian`.
- الطالب `student`.
- محرر الموقع `website-editor`.
- قارئ التقارير `report-viewer`.

الصلاحية لا تعتمد على اسم الدور فقط؛ تستخدم صلاحيات دقيقة مثل `students.create` و`recitations.create` و`reports.export` و`website.manage` و`users.manage`. إخفاء أي زر في الواجهة لا يكفي وحده؛ التحقق من الصلاحيات حاصل في الخادم وسياسات الوصول.

### ما يراه المحفّظ

- يرى حلقاته وطلابه ضمن إسناده الفعّال فقط.
- يستطيع تسجيل الحضور والتسميع لطلاب حلقته فقط.
- يستطيع فتح ملف الطالب وسجله السابق وملخص تقدمه.
- يستطيع إضافة الطلاب وتعديلهم وأرشفتهم ضمن نطاق حلقته إذا كانت صلاحياته تسمح بذلك.
- يحصل على رابط التطبيق داخل `/teacher/mobile-app` بعد تسجيل الدخول.
- لا يرى الهيكلية الإدارية العامة إلا بالقدر المرتبط بحلقته.

### ما يملكه مدير النظام

- إدارة الحسابات والأدوار والصلاحيات من صفحة التحكم بالوصول.
- إدارة المركز والحلقات والمحفظين والإسنادات.
- الوصول للتقارير والمحتوى والإعدادات وسجل التدقيق.
- نشر إصدارات Android للمحفظين من لوحة توزيع التطبيق.
- الحذف النهائي للطالب من سلة المهملات، وهي عملية محصورة به.

### الأمان الإضافي

- تسجيل الدخول والخروج واستعادة كلمة المرور وتغييرها وتأكيد العمليات الحساسة بكلمة المرور.
- فحص كلمة المرور في الوقت الفعلي مع زر إظهار/إخفاء.
- إدارة الجلسات والأجهزة، وإبطال الرموز عند تغيير كلمة المرور أو تعطيل الحساب.
- بنية 2FA ورموز الاستعادة موجودة، لكنها **معطّلة مؤقتًا** ما دام `TWO_FACTOR_AUTH_ENABLED=false`.
- عند تفعيل 2FA يمكن فرضه على الأدوار الإدارية والحساسة.

## 4. الهيكل التنظيمي والحلقات

يدعم النظام البيانات التالية:

- المركز.
- الفرع على مستوى البيانات للتوسع، مع عدم تحميل المحفّظ تفاصيله في تجربته اليومية.
- الحلقة: الاسم، الرمز المتسلسل، السعة، الحالة، تاريخ البداية، الملاحظات والجدول الأسبوعي.
- المحفّظون والموظفون.
- إسناد المحفّظ للحلقة بتاريخ بداية ونهاية ودور رئيسي أو مساعد.
- سجل التحاق الطالب بالحلقات؛ نقل الطالب لا يمحو تاريخه السابق.

مدير المركز يمكن أن يكون محفظًا في الوقت نفسه: حين يكون له ملف محفظ وإسناد فعّال لحلقة، تظهر له أدوات التسجيل اليومي الخاصة بمحفظي الحلقة.

## 5. إدارة الطلاب وأولياء الأمور

### ملف الطالب

لكل طالب ملف يحتوي على:

- رقم طالب متسلسل تلقائيًا.
- الاسم الرباعي، رقم الهوية، تاريخ الميلاد، رقم التواصل، تاريخ التسجيل والحالة.
- الصورة الشخصية والوثائق الحساسة في تخزين خاص.
- الحلقة الحالية والمحفظ الحالي وسجل الانتقال بين الحلقات.
- خط زمني للحضور والتسميع والملاحظات والإنجازات والدورات والشهادات.
- ملخص للتقدم: آخر حفظ، السور/الأجزاء، المتوسط، الحضور، والإنجازات.
- رابط واتساب مباشر عند وجود رقم تواصل صالح.

حالات الطالب: فعّال، موقوف، منسحب، متخرج، أو في سلة المهملات.

### الحذف وسلة المهملات

الحذف من قائمة الطلاب ليس حذفًا نهائيًا. ينقل الطالب إلى `/students/trash` ويخفيه من نتائج البحث والقوائم العادية. يستطيع المستخدم المخوّل:

- استعادة الطالب؛ ثم تحديد حلقة جديدة عند الحاجة.
- مشاهدة محتويات السلة والبحث فيها.
- تنفيذ حذف نهائي من المدير الأعلى فقط بعد تأكيد العملية.

### أولياء الأمور

ولي الأمر كيان مستقل وليس حقولًا مكررة في كل طالب. يمكن ربط ولي أمر واحد بأكثر من طالب، وتحديد:

- الاسم ورقم الهوية.
- رقم التواصل، رقم بديل وبريد اختياري.
- صلة القرابة، ولي الأمر الأساسي، وإذن تلقي الإشعارات.
- وثيقة الهوية في تخزين خاص عند توفرها.

لا تُخترع أرقام الهواتف أو بيانات الهوية الناقصة عند الاستيراد؛ تُستكمل لاحقًا حتى يظل التواصل عبر واتساب صحيحًا.

## 6. مرجع القرآن والحفظ اليومي

### مرجع القرآن

- مرجع ثابت يضم 114 سورة و6,236 آية.
- لكل آية ترتيب عام، ورقم سورة وآية، ومعلومات الجزء والحزب والصفحة عند توفرها.
- قوائم السور والآيات مرتبطة ببعضها: اختيار السورة يعرض آياتها تلقائيًا.
- لا يمكن تسجيل آية غير موجودة أو نطاق تنتهي فيه القراءة قبل بدايتها.

### شاشة اليومي للمحفّظ

المسار: `/teacher/daily`.

تمكّن المحفّظ من:

1. اختيار الحلقة واليوم والطالب.
2. تسجيل حالة الحضور: حاضر، متأخر، غائب، غائب بعذر.
3. إضافة أكثر من بند تسميع في اليوم نفسه.
4. اختيار نطاق حفظ أو مراجعة من السورة والآية إلى السورة والآية.
5. اختيار التقييم والملاحظات وعدد أخطاء الحفظ والتجويد والتردد والتنبيه.
6. مشاهدة كشف منظم للسجلات السابقة للطالب قبل التسجيل.

أنواع التسميع: حفظ جديد، مراجعة قريبة، مراجعة قديمة، سرد/تلاوة، اختبار، تجويد.

التقييمات: ضعيف، جيد، جيد جدًا، ممتاز. تحتفظ قاعدة البيانات بالقيم المعيارية بينما تعرض الواجهة التسمية العربية.

### قاعدة الغياب المهمة

الحالتان `غائب` و`غائب بعذر` تعاملان كغياب أكاديمي؛ لا يسمح النظام بتسجيل حفظ أو تقييم عام للطالب في ذلك اليوم. أما الحاضر والمتأخر فيسمح لهما بالتسجيل.

### الحفظ السابق والتقدم

- يمكن تسجيل خط أساس للحفظ قبل الالتحاق بالمركز، ولا يعامل كتسميع تم داخل المركز.
- يعتمد التقدم على سجلات التسميع الفعلية، لا على قيمة يدوية ثابتة.
- يحسب النظام الموضع الأخير، عدد الآيات، السور المكتملة، الأجزاء، المراجعات، متوسط التقييم والحضور.
- لأن منهج الحفظ يبدأ غالبًا من الجزء الثلاثين وصولًا إلى الفاتحة، يعرض النظام تقدير الأجزاء المحفوظة وفق هذا المسار؛ مثل الوصول إلى المجادلة أو الأحقاف بحسب الحدود القرآنية الفعلية.
- تظهر عبارات تشجيعية وواجهة تقدم داخل ملف الطالب دون جعلها مصدر بيانات مستقل.

## 7. التحليلات والتنبيهات ولوحات المتابعة

### لوحة المدير

تعرض مؤشرات فعلية وليست بيانات تجريبية، منها:

- عدد الطلاب الفعالين والحلقات والمحفظين.
- حضور اليوم، الغياب، جلسات التسميع والحفظ والمراجعة.
- الأداء الأسبوعي والشهري ومستويات الطلاب والحلقات.
- ترتيب الطلاب خلال الفترة: الأكثر حفظًا والأكثر التزامًا.
- مقدار الحفظ بالآيات وما يعادله تقريبًا من الأجزاء.
- أيام الحضور والغياب والنسبة ومؤشرات المتابعة.

### التنبيهات الذكية

ينشئ النظام تنبيهات قابلة للمتابعة والحل، مثل:

- تقييمات ضعيفة متكررة أو هبوط في المستوى.
- تأخر المراجعة أو غياب التسجيل اليومي.
- غياب واحد دون عذر خلال الشهر: تنبيه للمحفظ ومدير المركز.
- تجاوز ثلاثة أيام غياب بعذر في الشهر: يظهر التنبيه عند اليوم الرابع.

التنبيهات لها مستوى معلوماتي أو تحذيري أو حرج، وحالة مفتوحة أو محلولة، وتصل إلى المستخدمين المعنيين بحسب الإسناد.

## 8. الدورات والشهادات والإنجازات

من قسم `/academic` يمكن للإدارة:

- إنشاء الدورات وتحديد وصفها ومدربها وفترتها وساعاتها وحالتها.
- عرض طلاب المركز وتحديد طالب أو عدة طلاب أو الكل.
- تسجيل إنجاز الدورة والدرجة من 100 والتقييم وتاريخ الإنجاز والملاحظات.
- إصدار شهادات مرتبطة بالدورة أو مستقلة، مع الجهة المصدرة والرقم والتاريخ والملف الخاص.
- تسجيل إنجازات قرآنية أو مسابقات أو تكريمات وإنجازات يدوية.
- تصدير نتائج الدورات إلى Excel متضمنة الطالب والهوية والمركز والمحفظ والدورة والدرجة والتقييم والتاريخ والملاحظات.

## 9. التقويم والإشعارات والتقارير

### التقويم

يوفر عرضًا يوميًا/أسبوعيًا/شهريًا للحلقات والدورات والاختبارات والاجتماعات والأنشطة. يدعم التصفية بحسب الحلقة والنوع والفترة.

### مركز الإشعارات

- إشعارات قاعدة البيانات مع عداد غير المقروء.
- مسارات للتنبيهات والإصدارات والتقارير.
- يمكن تفعيل Reverb/Echo للإشعارات الفورية عند تجهيز مفاتيحهما في الإنتاج؛ يبقى التحديث العادي من قاعدة البيانات متاحًا عند عدم عمل WebSocket.

### مركز التقارير وExcel

يدعم تقارير الطلاب والحلقات والمحفظين والحضور والحفظ والمراجعة والتقييم والتنبيهات والدورات والشهادات والملخص الإداري. التصدير الكبير يعمل عبر الطابور ويملك حالات: قيد الإعداد، جاهز، فشل.

هناك نموذج كشف عربي RTL للمركز أو للمحفظ يشمل، عند توفر البيانات:

- المركز، الاسم الرباعي، الهوية وتاريخ الميلاد.
- بيانات ولي الأمر.
- المحفظ وهويته.
- السرد والحفظ من/إلى، وآخر موضع أو إنجاز.
- إجمالي الحفظ بالأجزاء.

ملفات التصدير محمية بالصلاحيات ولا تكون روابط عامة مفتوحة.

## 10. الموقع العام وCMS

### الموقع العام

الصفحات المتاحة تشمل: الرئيسية، عن المركز، البرامج، الأنشطة، الأخبار، الإنجازات، المعرض، التواصل، الصفحات المخصصة، `robots.txt` و`sitemap.xml`.

يستخدم الموقع هوية مركز الغفران وشعارًا دائريًا وخط Tajawal وانتقالات خفيفة تراعي تفضيل تقليل الحركة. يحتوي على:

- زر واتساب عائم برقم التواصل المعتمد `+972 56 797 3076`.
- قسم تواصل بصري ورمز QR لواتساب.
- خريطة المركز بالإحداثيات `31.382208090207207, 34.331760937834474`.
- عدم نشر أي بيانات أكاديمية أو شخصية للطلاب.

### إدارة المحتوى

من `/cms` يمكن للمحرر المصرح له إدارة الصفحات والأخبار والأنشطة والإعلانات والإنجازات العامة والصور. يدعم المحتوى حالات مسودة، منشور، مؤرشف، مع رفع صورة ومعاينة للنشر وحقول SEO.

## 11. تطبيق المحفّظ للجوال

### الوظائف

تطبيق Flutter خاص بالمحفظين على Android، ويقدّم:

- تسجيل الدخول الآمن لأول مرة بالإنترنت.
- تنزيل بيانات الحلقة والطلاب ومرجع السور والآيات وملف المحفظ.
- فتح ملف الطالب وتقدمه وإنجازاته وسجل التسميع.
- الحضور والتسميع اليومي واختيار الآيات والتقييم.
- إضافة طالب وتعديله وأرشفته ضمن الصلاحيات.
- إنشاء وتنزيل كشوف Excel الخاصة بحلقات المحفظ.
- العمل دون إنترنت بعد التهيئة الأولى.

### العمل دون إنترنت والمزامنة

يحفظ التطبيق البيانات المحلية في SQLite (Drift) ويضع عمليات الإدخال والتعديل في Outbox محلي. عند وجود الشبكة:

1. يرسل التغييرات المؤجلة إلى API.
2. يعالج الخادم التعارضات والتحقق والصلاحيات بنفس منطق الويب.
3. يعيد التطبيق التغييرات الجديدة ويحدث النسخة المحلية.

أول تسجيل دخول وتنزيل البيانات يتطلبان الإنترنت. بعد ذلك يستطيع المحفظ فتح طلابه وتسجيل الحضور والتسميع بلا اتصال، ثم تتم المزامنة تلقائيًا أو يدويًا عند عودة الإنترنت.

لا يخزن التطبيق المحلي وثائق الهوية أو الملفات الخاصة؛ تبقى في تخزين الخادم المحمي.

### التوزيع والتحديث

- التطبيق لا يحتاج Google Play حاليًا.
- يبنى APK Release موقّع بمفتاح ثابت محفوظ خارج Git.
- مدير النظام يرفع APK وملف SHA-256 وManifest من `/mobile-distribution`.
- الرفع يتم على دفعات ثنائية صغيرة بحجم 1MB مع شريط تقدم؛ هذا يعالج قيود الاستضافات المشتركة على رفع الملفات الكبيرة.
- يتحقق النظام من الإصدار والبناء والحجم والبصمة والتوقيع وواجهة API قبل النشر.
- APK محفوظ في `storage/app/private/releases` ولا ينشر من `public/`.
- المحفّظ يرى رابط التنزيل فقط بعد تسجيل الدخول في `/teacher/mobile-app`.
- التطبيق يفحص وجود إصدار أحدث، يتحقق من البصمة والتوقيع، ثم يطلب من المستخدم تأكيد التثبيت. لا يستطيع Android تثبيت التحديث بصمت دون موافقة المستخدم.

## 12. API v1

المسار الأساسي: `/api/v1`، ويعيد الترويسة `X-API-Version: 1`.

### المصادقة

- `POST /auth/login`
- `POST /auth/two-factor-challenge` عند تفعيل المصادقة الثنائية
- `GET /user`
- `POST /auth/logout`
- `GET /meta` متاح دون تسجيل دخول لوصف عقد API

تستخدم تطبيقات الجوال Bearer Token من Sanctum مع قدرات مثل `mobile:read` و`mobile:sync` و`mobile:export`. تنتهي الرموز الافتراضيًا بعد 30 يومًا، وتُسحب عند تعطيل الحساب أو تغيير كلمة المرور.

### الموارد الأساسية

- الحلقات والطلاب وملف الطالب وتقدمه وسجلاته اليومية.
- الحضور والتسميع والشهادات والدورات.

## 16. النشر على Hostinger وGitHub Actions

Workflow النشر موجود في `.github/workflows/production.yml` ويعمل بالترتيب:

```text
Push / Pull Request
      ↓
composer validate + composer install
      ↓
npm ci + npm run build
      ↓
php artisan test
      ↓
حفظ أصول الواجهة المبنية
      ↓
النشر عبر SSH إلى Hostinger عند استيفاء شروط فرع الإنتاج
```

النشر لا يبدأ إلا بعد نجاح الجودة والبناء. يعتمد على GitHub Secrets وVariables لإعدادات SSH ومسار المشروع والنطاق وفرع الإنتاج؛ لا تضع هذه القيم داخل المستودع.

قبل اعتماد الإنتاج يجب تنفيذ ما يلي على الاستضافة:

- تعيين `APP_ENV=production` و`APP_DEBUG=false` و`APP_URL=https://algofran-center.tech`.
- إعداد MySQL وSMTP وHTTPS.
- تشغيل `php artisan migrate --force` ضمن النشر، دون أوامر تمسح البيانات.
- جعل `storage` و`bootstrap/cache` قابلين للكتابة للمستخدم الصحيح.
- إعداد Cron للمجدول وWorker للطابور إن كانت الباقة تدعم ذلك.
- إعداد النسخ الاحتياطي خارج خادم الويب وتجربة الاستعادة.
- تشغيل `php artisan system:production-check` بعد ضبط البيئة.
- ضبط Reverb فقط عند الحاجة الفعلية للإشعارات الفورية، مع إبقاء fallback قاعدة البيانات.

راجع التفاصيل التنفيذية في `docs/LAUNCH_GUIDE.md` و`docs/PRODUCTION.md`.

## 18. حدود يجب معرفتها قبل الاستخدام الفعلي

- لا تضاف بيانات إنتاج أو أرقام هويات أو أرقام هواتف داخل Seeders أو ملفات Git أو commits.
- إدخال البيانات على الدومين يحدث في قاعدة بيانات Hostinger؛ قاعدة بيانات التطوير المحلية مختلفة عنها.
- لا تستخدم `migrate:fresh` أو `db:wipe` أو أوامر حذف شاملة على قاعدة الإنتاج.
- الاستيراد الجماعي للطلاب من Excel ليس مسارًا عامًا منشورًا بعد؛ الإدخال الحالي يتم من لوحة الطلاب أو عبر أداة استيراد محمية تُبنى خصيصًا عند الحاجة.
- 2FA موجودة في النظام لكن تفعيلها قرار تشغيلي لاحق، وليس مفعلة افتراضيًا حاليًا.
- التطبيق متاح حاليًا لـ Android كـ APK خاص بالمركز، وليس تطبيقًا منشورًا في Google Play أو iOS App Store.
