# قرار تسليم الجوال وعقد التوافق

## القرار الحالي

يعتمد النظام تطبيق **Flutter أصليًا للمحفّظ** على Android، مع Laravel API v1 كمصدر البيانات الرسمي. يدعم التطبيق التسجيل اليومي، وملف الطالب وإنجازاته، وملف المحفظ، وتصدير الكشوف، وإضافة طلاب الحلقة وتعديلهم وأرشفتهم.

يُحفظ السجل أولًا محليًا في SQLite، لذلك يستطيع المحفّظ العمل داخل الحلقة دون إنترنت بعد أول دخول وتنزيل بيانات الحلقة. عند عودة الاتصال والتطبيق مفتوح يحاول المزامنة مباشرة، وتوجد مهمة خلفية دورية كل 15 دقيقة؛ توقيتها الفعلي يخضع لقيود Android والبطارية وليست ضمانًا للمزامنة الفورية بعد إغلاق التطبيق قسرًا. يبقى زر المزامنة اليدوية متاحًا.

الويب وFlutter يستخدمان منطق Laravel نفسه، ولا يوجد منطق اعتماد أكاديمي مكرر داخل التطبيق.

## سلامة المزامنة

- لكل جهاز UUID مستقل ولكل عملية مزامنة UUID ثابت.
- الخادم يحفظ إيصال العملية ويمنع إنشاء سجلين عند إعادة إرسالها.
- السجل الرسمي الموجود مسبقًا لا يُستبدل بصمت؛ يعاد تعارض واضح للتطبيق.
- إنشاء الطالب Offline يستخدم `client_uuid` محليًا ثم يربطه التطبيق بمعرّف الخادم قبل إرسال أي تسميع تابع له.
- تعديل الطالب يستخدم `base_updated_at`؛ التعديل القديم يتحول إلى تعارض ولا يكتب فوق الملف الرسمي.
- حذف الطالب من الجوال أرشفة قابلة للتتبع تحفظ كل السجلات، وليس حذفًا نهائيًا.
- يتحقق الخادم من المحفّظ والحلقة والطالب والصلاحيات قبل كشف السجل أو اعتماده.
- حالات التطبيق المحلية هي: قيد الانتظار، قيد المزامنة، معتمد، متعارض، فاشل مؤقتًا، ومرفوض نهائيًا.
- الفشل المؤقت يعاد تلقائيًا، أما السجل المرفوض فلا يعاد إرساله حتى يراجعه المحفّظ.
- يمنع تسجيل الخروج أو تبديل الحساب عند وجود سجلات غير محسومة، حتى لا تضيع أو تُرسل باسم مستخدم آخر.
- رمز Sanctum محفوظ في مخزن النظام الآمن، وليس في SQLite.

## عقد API v1

- المسار ثابت تحت `/api/v1`، وكل استجابة تحمل `X-API-Version: 1`.
- `GET /api/v1/meta` يعلن حالة الإصدار وأدنى إصدار عميل مدعوم.
- المصادقة تستخدم Sanctum token محدد القدرة والمدة والجهاز.
- القراءة تتطلب `mobile:read`، والرفع يتطلب `mobile:sync` بالإضافة إلى صلاحيات الحضور والتسميع.
- نقاط التطبيق الأساسية:
  - `POST /api/v1/auth/login`
  - `GET /api/v1/mobile/bootstrap`
  - `GET /api/v1/mobile/sync/changes`
  - `POST /api/v1/mobile/sync/daily-records`
  - `POST /api/v1/mobile/sync/student-operations`
  - `GET /api/v1/mobile/profile`
  - `GET /api/v1/mobile/students/{student}/profile`
  - `POST /api/v1/mobile/report-exports`
  - `POST /api/v1/auth/logout`
- الأخطاء تستخدم `message` و`error.code`، وتضيف `error.fields` عند فشل التحقق.
- لا تتغير دلالة الحقول الحالية داخل v1؛ أي تغيير كاسر ينتقل إلى `/api/v2`.

## قناة النشر والتحديث المعتمدة — دون Google Play

بطلب المستخدم يعتمد Android حزمة **APK Release موقّعة** خاصة بمحفظي المركز، وتتصل حصريًا بـ`https://algofran-center.tech/api/v1`. لا توجد صفحة تحميل عامة: التنزيل الأول يتم من `/teacher/mobile-app` بعد تسجيل الدخول بحساب محفظ فعّال، والتحديثات اللاحقة تتطلب رمز الجهاز الخاص بالمحفّظ. هذه القناة ليست متجرًا ولا تثبيتًا صامتًا: المحفّظ يوافق على التثبيت من هذا المصدر وعلى كل تحديث من شاشة Android. لا تتضمن هذه الجولة إصدار iOS.

- يعرض نظام المحفظ رابط التنزيل فقط بعد تفعيل الإصدار والتحقق من ملف APK وبصمته وmanifest مطابق للنطاق والإصدار.
- ملفات الإصدار الثلاثة محفوظة في `storage/app/private/releases`، وليست ضمن `public/storage`. التنزيل يتم عبر endpoint محدد يتطلب حسابًا نشطًا ورمز Sanctum بقدرة القراءة وملف محفظ فعّال؛ ولا يكشف باقي الملفات الخاصة.
- يفحص التطبيق `/api/v1/mobile/releases/latest` برقم البناء المثبت فعليًا بعد تسجيل الدخول، وعند فتح الصفحة الرئيسية أو استئنافها وبعد المزامنة، مع تقييد تكرار الفحص، ويعرض إشعار تحديث داخله. يتوفر كذلك خيار «التحقق من تحديث التطبيق» في القائمة.
- يتحقق قبل التثبيت من الحجم وSHA-256، ويمنع تحويل التنزيل إلى نطاق آخر أو اتباع redirects. التنزيل لا يحمل رمز الدخول.
- يتحقق Android من هوية الحزمة ورقم البناء وتطابق التوقيع وعدم قابلية الحزمة للتصحيح قبل فتح المثبت.
- يمنع مسار التحديث داخل التطبيق التثبيت بوجود عمليات غير متزامنة، ويعيد الفحص بعد التنزيل. إلغاء شاشة التثبيت لا يمنع إعادة فتحها.
- فشل فحص التحديث لا يعطل العمل دون اتصال. التنبيه «مهم» لا يوقف وصول المحفّظ إلى بياناته المحلية.

## التوقيع والبناء

مفتاح الإنتاج الدائم: `mobile/android/keystore/gofran-release.jks`، وإعداداته السرية: `mobile/android/key.properties`. كلاهما مستبعد من Git. **احتفظ بهما معًا في نسخة احتياطية مشفرة خارج الحاسوب؛ فقد المفتاح يمنع تحديث النسخ المثبتة. لا ترفعهما إلى الاستضافة.**

سكربت `initialize_release_key.ps1` ينشئ مفتاحًا جديدًا فقط عند غياب الملفين ويرفض استبدالهما. لا يُشغّل مجددًا عند إصدار تحديث؛ استخدم المفتاح الأصلي.

من جذر المشروع، بعد تثبيت Flutter 3.41.9 وAndroid SDK:

```powershell
powershell -ExecutionPolicy Bypass -File mobile/scripts/build_release_apk.ps1 -ApiBaseUrl https://algofran-center.tech/api/v1 -BuildName 1.3.1 -BuildNumber 5
```

السكربت ينفذ تحليل Flutter واختباراته ويبني Release ويفحص التوقيع والهوية والإصدار عبر أدوات Android الرسمية. الملفات الناتجة:

```text
mobile/build/releases/gofran-mobile-1.3.1-5.apk
mobile/build/releases/gofran-mobile-1.3.1-5.apk.sha256
mobile/build/releases/gofran-mobile-1.3.1-5.apk.json
```

ارفع الملفات الثلاثة إلى `storage/app/private/releases` في الخادم، ثم عيّن في `.env` الإنتاجي:

```dotenv
MOBILE_APP_RELEASE_ENABLED=true
MOBILE_APP_VERSION=1.3.1
MOBILE_APP_VERSION_CODE=5
MOBILE_APP_MINIMUM_VERSION_CODE=1
MOBILE_ANDROID_APK_PATH=releases/gofran-mobile-1.3.1-5.apk
MOBILE_APP_RELEASE_NOTES="الإصدار الرسمي للمركز مع المزامنة وتحديثات التطبيق"
```

نفذ `php artisan config:cache` ثم سجّل دخولك بحساب محفظ فعّال وافحص صفحة `/teacher/mobile-app` والتنزيل من هاتف. لا تستبدل ملف إصدار منشور؛ لكل تحديث رقم بناء أعلى وملفات جديدة. مثال التحديث التالي `1.3.2+6`. يمكن الرجوع مؤقتًا إلى إعداد نشر سابق بالخادم، لكن Android لا يقبل تخفيض رقم إصدار مثبت.

## البناء عبر GitHub

Workflow: `.github/workflows/mobile-release.yml`، تشغيل يدوي من الفرع المعتمد بعد رفع الكود. يختبر ثم يبني ويرفق الملفات الثلاثة كـArtifact؛ **لا ينشرها تلقائيًا على Hostinger**.

1. عرّف Repository variable `MOBILE_RELEASE_BRANCH=gofran/T1` (شرط تشغيل الوظيفة يقرأ متغير المستودع).
2. أنشئ Environment باسم `mobile-release` وقيّد فروعه إلى الفرع المعتمد.
3. متغيراته: `MOBILE_API_BASE_URL=https://algofran-center.tech/api/v1`، و`ANDROID_SIGNING_CERTIFICATE_SHA256` من manifest أول إصدار موثوق.
4. أسراره: `ANDROID_KEYSTORE_BASE64` محتوى مفتاح التوقيع بصيغة Base64، و`ANDROID_KEY_PROPERTIES_BASE64` محتوى ملف الإعدادات بصيغة Base64. أدخلها عبر واجهة GitHub الآمنة، ولا تطبعها في السجلات أو تضعها في المستودع. Base64 ترميز وليس تشفيرًا.
5. شغّل **Signed Android release** برقم إصدار وبناء جديد، نزّل Artifact وارفع ملفاته الثلاثة، ثم حدّث إعدادات الإصدار بالخادم.

## الانتقال من التجربة

النسخة `gofran-mobile-1.2.0-test.apk` تستخدم توقيع Debug وعنوان الشبكة المحلية. **لا يمكن تحديثها مباشرة بالمفتاح الرسمي الجديد.** صِلها بالخادم المحلي القديم وأكمل مزامنة جميع السجلات واحسم التعارضات أولًا، ثم احذفها وثبّت النسخة الرسمية وسجّل الدخول بحساب الإنتاج. حذف التطبيق يحذف البيانات المحلية غير المرسلة.

إذا بدأت الإنتاج بقاعدة جديدة فارغة، فلن تنتقل بيانات التجربة تلقائيًا. لا تحذف قاعدة التجربة من أجل النشر؛ أنشئ قاعدة إنتاج مستقلة وفق [دليل الإطلاق](LAUNCH_GUIDE.md).

تحديث Laravel عبر Workflow لا يحدّث كود Flutter المثبت. تغييرات API المتوافقة لا تحتاج حزمة جديدة، أما شاشات التطبيق وميزاته فتحتاج APK جديدًا بنفس `applicationId` والتوقيع وبرقم بناء أعلى.

المراجع الرسمية: [بناء وتوقيع Android في Flutter](https://docs.flutter.dev/deployment/android)، [التحقق من التوقيع عبر apksigner](https://developer.android.com/tools/apksigner)، و[أسرار GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).
