# قرار تسليم الجوال وعقد التوافق

## القرار

يعتمد النظام مسار **PWA-first** للمرحلة التالية من التسليم بدل إنشاء تطبيق أصلي مستقل الآن. الواجهة الحالية عربية RTL ومتجاوبة وتغطي منطق العمل كاملًا، بينما API v1 جاهزة لتطبيق أصلي مستقبلًا دون تكرار الخدمات أو الصلاحيات.

لا تُفعّل مزايا offline للبيانات الحساسة في هذا الإصدار. عند إضافة Service Worker لاحقًا يُسمح بتخزين shell والأصول العامة فقط، ويُمنع تخزين ملفات الهوية والتقارير ونتائج API الخاصة في Cache Storage.

## أسباب القرار

- نشر تحديث واحد للويب والجوال وتقليل ازدواج منطق الأعمال.
- الحفاظ على صلاحيات Laravel وStudentVisibility وسياسات الملفات في نقطة واحدة.
- تجربة RTL وخط Tajawal موجودة بالفعل على المقاسات الصغيرة.
- يمكن الانتقال إلى تطبيق أصلي عندما تصبح الإشعارات الأصلية أو العمل الميداني دون اتصال مطلبًا مثبتًا.

## عقد API v1

- المسار ثابت تحت `/api/v1`، وكل استجابة تحمل `X-API-Version: 1`.
- `GET /api/v1/meta` يعلن حالة الإصدار وأدنى إصدار عميل مدعوم.
- الأخطاء تستخدم دائمًا `message` و`error.code`، وتضيف `error.fields` عند فشل التحقق.
- المصادقة تستخدم Sanctum tokens محددة القدرة والمدة والجهاز.
- عند تفعيل 2FA تستخدم الأجهزة challenge token قصير العمر وأحادي الاستخدام قبل إصدار Bearer token.
- لا تُزال الحقول الحالية ولا يتغير معناها داخل v1؛ الإضافات الجديدة اختيارية. أي تغيير كاسر ينتقل إلى `/api/v2`.

## الزمن الحقيقي وFallback

تستمع PWA عبر Echo إلى قناة المستخدم الخاصة لإشعارات التنبيهات الحرجة واكتمال التصدير. قاعدة البيانات هي المصدر الدائم، وpolling كل 30 ثانية هو fallback عند غياب Reverb أو انقطاع الشبكة.

## متى ننتقل إلى تطبيق أصلي

يُعاد القرار فقط عند وجود حاجة مؤكدة إلى إشعارات Push الأصلية، تكامل عتاد الجهاز، توزيع عبر المتاجر، أو مزامنة ميدانية دون اتصال. حتى ذلك الوقت تبقى PWA أقل مخاطرة وأسرع تسليمًا.
